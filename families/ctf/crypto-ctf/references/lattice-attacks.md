# Lattice-Based Attacks

Using lattice reduction (LLL, BKZ) to solve cryptographic problems.

## Core Concepts

A **lattice** is a discrete set of points in R^n generated by integer
linear combinations of basis vectors. The **Shortest Vector Problem**
(SVP) and **Closest Vector Problem** (CVP) are hard in general but
approximable by LLL in polynomial time.

**LLL** (Lenstra-Lenstra-Lovász) finds a "short" basis vector in
polynomial time. The approximation factor is 2^((n-1)/2) for SVP,
but in practice it often finds much shorter vectors.

## When Lattices Apply

Lattice attacks apply when a cryptographic problem can be reformulated
as finding a short or close vector in a lattice:

- RSA with partial information (Coppersmith — see `rsa-coppersmith.md`)
- ECDSA biased nonces (Hidden Number Problem)
- Knapsack/subset-sum problems
- LWE (Learning With Errors) cryptosystems
- Approximate GCD
- Integer relation finding (PSLQ / LLL)

## Hidden Number Problem (HNP)

**When**: Recover a secret d from equations of the form
t_i ≡ d * a_i + e_i (mod q) where e_i is small (biased nonces,
partial leaks).

```python
# SageMath — HNP via CVP/LLL
# Given: a_i, t_i, bound on |e_i| < B, modulus q
# Construct lattice:
n = len(samples)
M = matrix(ZZ, n + 2, n + 2)
for i in range(n):
    M[i, i] = q
M[n, :n] = vector(ZZ, a_values)
M[n, n] = B / q  # scaling
M[n+1, :n] = vector(ZZ, t_values)
M[n+1, n+1] = B

# LLL reduce
L = M.LLL()
# The short vector contains the secret d (after unscaling)
```

## Approximate GCD

**When**: Given x_i = p * q_i + r_i where p is secret, q_i are
large, and r_i are small errors.

**How**: Build a lattice where the short vector reveals p.

```python
# SageMath
# Given samples x_0, x_1, ..., x_n
# Construct:
M = matrix(ZZ, n+1, n+1)
M[0, 0] = 2^(rho+1)  # rho = bit length of error
for i in range(1, n+1):
    M[i, 0] = x_values[i]
    M[i, i] = -x_values[0]
L = M.LLL()
# Recover p from short vector
```

## Knapsack / Subset Sum

**When**: Given a set of weights w_i and target sum S, find which
subset sums to S. Used in Merkle-Hellman and similar cryptosystems.

```python
# SageMath — low-density knapsack
n = len(weights)
M = matrix(ZZ, n + 1, n + 2)
for i in range(n):
    M[i, i] = 1
    M[i, n + 1] = weights[i]
M[n, n] = 1
M[n, n + 1] = -S
# Scale the last column appropriately
L = M.LLL()
# Look for row with entries in {0, 1} and last entry 0
```

## Integer Relations (LLL for Constants)

**When**: Find integer coefficients c_i such that
sum(c_i * x_i) = 0 (or ≈ 0) for known real/rational values x_i.

```python
# SageMath — find integer relation
# E.g., express a crypto value as combination of known constants
vals = [...]  # known values
n = len(vals)
M = matrix(ZZ, n, n + 1)
for i in range(n):
    M[i, i] = 1
    M[i, n] = int(vals[i] * 10^precision)
L = M.LLL()
# Short vector gives integer coefficients
```

## Practical Tips

1. **Scaling matters**: Different columns may need different scaling
   to make the target vector "short" relative to other basis vectors.

2. **BKZ vs LLL**: BKZ (Block Korkine-Zolotarev) with higher block
   size gives better reduction but is slower. Try LLL first, increase
   to BKZ(20), BKZ(30), etc. if needed.

3. **Dimension**: Lattice attacks become harder as dimension increases.
   Most CTF instances are designed to be solvable with n < 100.

4. **Debugging**: Check that the expected solution is actually a
   short vector in your lattice before reducing. Compute
   `target.norm()` vs `det(L)^(1/n)` — target should be much shorter.

5. **fpLLL**: For performance-critical lattice work, use `fpLLL`
   (available via SageMath or standalone C++ library).
